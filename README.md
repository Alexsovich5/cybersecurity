# Cybersecurity Hardening Lab

A Docker lab that hardens CentOS 7 hosts and watches them. A Bash script and an Ansible playbook apply SSH, password-aging, firewalld, auditd, sysctl and fail2ban settings idempotently. A Snort 2.9 sensor built from source alerts on four local rules. OSSEC in local mode watches auth and audit logs. Filebeat ships both alert streams, plus auth, audit and simulated pfSense firewall logs, through a Logstash pipeline into dated `security-*` Elasticsearch indices, and Logstash emails high-priority Snort alerts. A small CLI then finds source IPs seen by both Snort and OSSEC and writes them out as Ansible variables, and a response playbook blocks those IPs with firewalld rich rules.

Personal project built on the 2018-era stack (Ansible 2.4, Snort 2.9, OSSEC 2.9, Elastic Stack 6.3, Bash on CentOS 7).

## Status

**Implemented**

- `scripts/harden_linux.sh`: idempotent CentOS 7 hardening (sshd options, password aging, firewalld default-drop zone allowing ssh/https, unneeded services, file permissions, auditd watch rules, kernel sysctls, fail2ban sshd jail) with `--check`, `--root`, `--skip-services` and `--skip-packages`; it prints `CHANGED:` only when it modifies something.
- Ansible hardening play (tag `hardening`): installs aide, rkhunter, clamav, fail2ban, audit and firewalld at exact versions, then runs the script; a second run reports `changed=0`.
- `scripts/setup_snort.sh`: builds DAQ 2.0.6 and Snort 2.9.11.1 from sha256-checked source tarballs and installs the config.
- `config/snort.conf` passes `snort -T`, with frag3/stream5 and fast alert output, plus four local rules: lab ICMP probe, telnet connection attempt, nmap XMAS scan, and an SSH SYN burst using `detection_filter`.
- `scripts/deploy_ossec.sh`: builds OSSEC 2.9.4 in local mode from sha256-checked source, with JSON alert output, monitoring of `/var/log/secure`, the audit log and a lab input file, and local rules for refused root logins and repeated SSH failures.
- Ansible plays for Snort (tag `snort`, group `ids_sensors`) and OSSEC (tag `ossec`, all hosts) that reuse the install scripts; service start is controlled by a variable.
- Filebeat 6.3.2 config that ships Snort alerts, OSSEC `alerts.json`, `/var/log/secure` and the audit log to Logstash, tagging each event with `fields.log_type`, plus an Ansible play (tag `filebeat`) that installs and configures it.
- Logstash 6.3.2 pipeline: Beats input and UDP syslog input, grok for Snort fast alerts, OSSEC JSON field mapping, pfSense `filterlog` CSV parsing for IPv4 TCP/UDP, GeoIP on `src_ip`, per-type dated indices, and an email for Snort priority 1 and 2.
- Elasticsearch index template for `security-*` that maps IP fields as `ip`, `geoip.location` as `geo_point`, and priority and level as `integer`.
- `tools/correlate.py`: queries Elasticsearch over a time range and reports source IPs that appear in both Snort and OSSEC events within a time window, as a table, JSON, or Ansible extra-vars.
- `ansible/respond_block_ip.yml`: validates a list of IPs and adds or removes firewalld rich rules in the `drop` zone, idempotently, using `firewall-offline-cmd` when firewalld is not running.
- Docker lab (`docker-compose.yml`): Elasticsearch, Logstash, Kibana, Filebeat, a Snort sensor sniffing the lab network, an OSSEC host, an SSH-managed CentOS 7 target, MailHog and a test runner.
- `tools/traffic.py` writes pcaps or sends live packets matching each local Snort rule plus benign traffic; `tools/pfsense_sim.py` sends recorded pfSense `filterlog` lines as syslog.

**Not implemented / known limitations**

- pfSense is simulated by tools/pfsense_sim.py; never run against a real pfSense. No pfSense appliance install, firewall rules, NAT or VPN (OpenVPN/IPsec) configuration.
- Email goes to MailHog; no real SMTP relay or mailbox is used.
- Servers and sensors are CentOS 7 containers without systemd. Service start, restart and enable paths (sshd, auditd, fail2ban, Snort, OSSEC, Filebeat, ELK units) are only lint- and syntax-checked.
- Hostile traffic is generated by scapy on an isolated Docker network. SSH brute force is simulated by appending real sshd log lines to OSSEC's lab input file.
- The `elk`-tagged ELK server play is illustrative only: it is pinned to 6.3.2, syntax-checked and linted, but never executed. The lab's ELK stack comes from the official 6.3.2 Docker images.
- OSSEC runs in local mode on every host: no server/agent mode, no central manager, no key exchange and no active response. Blocking is done by the response playbook.
- Correlation polls Elasticsearch on demand by source IP and time window only. There is no real-time or streaming correlation, and hosts behind the same NAT cannot be told apart.
- No incident-reduction or other business metric is measured.
- No compliance mapping or CIS benchmark scoring; only the technical parts (auditd rules and central audit-log shipping) exist.
- AIDE, rkhunter and ClamAV are installed but no scans are scheduled or reported. ClamAV is 0.99.2 with an empty signature set, because newer EL7 builds of the time are no longer downloadable.
- No Snort community or registered ruleset (no Oinkcode, no PulledPork); only the four local rules are used and tested. Snort sees only traffic that reaches its own container on the compose bridge, not a SPAN or TAP.
- No Kibana dashboards or saved searches; Kibana is only for browsing indices.
- The full-system package update task exists behind `hardening_update_all_packages: false` and is not tested.
- No Debian/Ubuntu support; the script and plays are CentOS/RHEL 7 only.
- OS packages are the CentOS 7.5 GA builds with no later errata, so the lab lacks security fixes released after May 2018.
- The SSH key for the target container is generated at container start into a Docker volume and is for the lab only.
- The images are amd64-only and run slowly under emulation on ARM hosts. Elasticsearch runs with machine learning disabled and may need `vm.max_map_count=262144` on Linux hosts.

## Running it

Everything runs in Docker images from the project's era, so nothing needs installing locally beyond Docker.

```bash
make build               # build the base, tests, snort, ossec and target images
make lab-up              # start Elasticsearch, Logstash, Kibana, Filebeat, MailHog, Snort, OSSEC and the target
make demo                # send traffic and log lines, show index counts, correlate and block the shared IP
```

Kibana is published on http://localhost:20856 and MailHog on http://localhost:20825. `make lab-down` stops the lab and removes its volumes.

## Tests

```bash
make test                # runs the suite inside the period image
```

The tests cover static checks, unit tests for the Python tools and the hardening script, Snort and OSSEC detection against generated traffic and log fixtures, idempotent Ansible runs against the target container, the Filebeat to Logstash to Elasticsearch pipeline, and the end-to-end detect, correlate and block flow; nothing is run against real hosts, a real pfSense or a running systemd.
